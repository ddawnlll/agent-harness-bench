# Contributing

Thanks for helping make coding-agent evaluation more reproducible.

## Before opening a pull request

Run the full gate from the repository root:

```bash
python3 tools/make_charts.py --check
python3 tools/check_svg.py
python3 tools/check_contrast.py
python3 tools/build_site.py --check
python3 tools/check_publish.py
python3 tools/verify_publication.py
python3 -m unittest discover -s tests -p "test_*.py" -v
```

A pull request must not:

- change published numbers without a new, separately identified run;
- regenerate figures by hand-editing SVG;
- introduce secrets, home paths, hostnames or IP addresses;
- weaken determinism (`make_charts.py --check` must stay byte-identical);
- present the nine-trial result as a universal ranking.

## Adding an agent or a task

An agent adapter must use the same provider endpoint, model identifier and
reasoning effort as the rest of the field, and must route **all** traffic
(including subagents) through the recording relay. A new task needs:

1. a public `TASK.md` and a frozen starting commit;
2. a hidden acceptance suite stored outside the workspace;
3. a reference solution that passes, and negative controls that fail the
   intended P0 gates;
4. deterministic fixtures and a documented scoring rule;
5. a new, secret set of hidden cases for any future competitive edition —
   the graders in this repository are a frozen, public edition.

## Reporting a problem

Open an issue with the repository version, the command you ran, and the
publication audit output. For security findings, follow `docs/SECURITY.md`
rather than opening a public issue.

## Style

- Prose: measured, specific, no marketing claims.
- Charts: generated by `tools/make_charts.py`, never edited by hand.
- Numbers: every published value must be reproducible from
  `results/publication-data.json` and its provenance record.
